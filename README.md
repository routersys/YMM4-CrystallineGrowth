[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-CrystallineGrowth.svg)](https://github.com/routersys/YMM4-CrystallineGrowth/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、素材の縁を結晶の核とみなし、Gravner–Griffeathの雪結晶成長モデルで氷晶を成長させて霜として描画する映像エフェクトプラグインです。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
氷晶の形は素材とシードから決定論的に決まり、同じ設定では常に同じ形になります。
強さ、凍結度、樹枝化、ファセット、到達距離、ゆらぎ、白濁、屈折、光沢の9項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「氷晶成長」として表示されます。カテゴリは装飾とアニメーションです。

入力された現在のフレームの不透明度から素材の形を求め、六角形のセルを敷き詰めた格子の上で、素材の縁にあたるセルを結晶の核にします。氷晶の成長の計算に使う格子モデルは、Gravner and Griffeathの論文「Modeling snow crystal growth II: A mesoscopic lattice map with plausible dynamics」（Physica D、2008年）に基づきます。水蒸気の拡散、凍結、付着、融解、ゆらぎの5つの処理を1ステップとし、このステップを繰り返して氷晶を成長させます。同じ素材、同じシード、同じパラメータからは、常に同じ形の氷晶ができます。

求めた氷晶は、氷として描画して素材の上へ重ねます。氷は白く濁り、氷越しの素材を屈折させ、表面に光沢を持ちます。各セルが結晶に加わったステップの記録を、成長の記録と呼びます。描画するのは、成長の記録のうち、凍結度で決めた途中までです。凍結度をアニメーションで変えると、素材が縁から凍りついていく様子になります。

計算はComputeWeaveの計算シェーダーがDirect3D 12で実行します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。通常のフレーム処理では、CPUへの画素の読み戻しを行わず、10個の整数の読み戻しだけで素材の変化を判定します。素材の形と大きさ、成長に関わるパラメータが変わらないフレームでは、成長の計算を再利用します。成長を計算し直したときだけ、成長の記録を読み戻します。この記録から、凍結度で表示している氷晶を囲む矩形をフレームごとに求め、描画はこの矩形の範囲だけで行います。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-CrystallineGrowth/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「氷晶成長」を選択してください。

## 主な機能

### 1. 氷晶の成長

成長は、平面を六角形のセルで隙間なく敷き詰めた格子の上で計算します。各セルは6つのセルと隣り合い、結晶はこの6つの方向に沿って伸びます。枝や平らな面の向きは、実際の雪結晶と同じく60度ごとに揃います。

不透明度が5%を超える画素が1つでもあるセルを素材の内側とし、内側のセルのうち外側のセルと接するセルを結晶の核にします。透明な部分の無い素材では、素材の四辺が縁になります。

各セルは、結晶に加わったかどうかと、水蒸気の量、擬似液体層の量、氷の量の4つの状態を持ちます。擬似液体層は、氷点下の氷の表面を覆う、液体に近い薄い水の層です。

1ステップでは、水蒸気の拡散、結晶の縁での凍結、付着、融解、ゆらぎの順に処理します。凍結では、結晶に接するセルの水蒸気の一部が氷に、残りが擬似液体層に変わります。付着では、擬似液体層の量がしきい値に達したセルが結晶に加わります。しきい値は、隣のセルのうち結晶に加わっているセルの数で変わり、結晶の先端では高く、くぼみでは低くなります。融解では、結晶に接していながら結晶に加わらなかったセルで、擬似液体層と氷のごく一部が水蒸気に戻ります。

結晶への加わりやすさが先端かくぼみかで変わるため、結晶は向きによって伸び方が違ってきます。この性質を付着の異方性と呼びます。付着の異方性によって、実際の雪結晶に見られる平らな結晶面と樹枝の分岐が生まれます。この平らな結晶面をファセットと呼びます。

成長を進めるステップ数は到達距離から決まり、品質ごとの上限を超えません。決め方は「品質の選択」にあります。

### 2. 凍結度と凍りつく様子

凍結度は、成長の記録をどこまで表示するかを決めます。成長の記録には、各セルが結晶に加わったステップが残り、表示はこのステップの順に進みます。凍結度が決めるのは表示だけで、成長の計算には影響しません。0%では何も描画せず、値を上げると氷晶が素材の縁から外側と内側の両方へ伸びていきます。セルが最後に結晶に加わったステップを100%とし、凍結度が50%なら、そのステップ数の半分までに結晶に加わったセルを表示します。

凍結度のデフォルトは100%なので、エフェクトを追加すると、計算したステップをすべて終えた形が表示されます。凍結度を0%から100%へアニメーションで変えると、テキストや立ち絵が縁から凍りついていく演出になります。

### 3. 樹枝化とファセット

樹枝化は、格子を満たす水蒸気の密度を決めます。低いほど板状にまとまり、高いほど樹枝状に枝分かれします。

パラメータの「ファセット」は、付着の異方性の強さを決めます。「ファセット」を上げると、結晶の先端や平らな縁にあるセルは、擬似液体層の量がより多くなるまで結晶に加わりません。そのため先端が伸びにくくなり、結晶面が平らに揃って板状の輪郭になります。「ファセット」が低いほど、枝が細かく分かれます。

Gravner and Griffeathの論文によると、氷晶の形は水蒸気の密度と先端や平らな縁のしきい値によって、板状、扇状、樹枝状、シダ状へ連続的に移り変わります。樹枝化は水蒸気の密度を、「ファセット」は先端や平らな縁のしきい値を決めます。

### 4. 到達距離とゆらぎ・シード

到達距離は、縁から霜が広がる距離の上限を、素材の長辺に対する割合で決めます。素材の長辺は、透明な部分も含む素材全体の長辺です。どの核のセルからも上限より遠いセルは、結晶に加わりません。上限は縁の外側と内側の両方に適用します。上限が1セルの幅より短いときは、1セルの幅を上限にします。

計算領域は、透明な部分も含む素材全体の上下左右に、到達距離と80画素の余白を加えた大きさです。到達距離を大きくするほど計算領域が広がり、ステップ数も増えるので、処理が重くなります。1セルの幅は計算領域の長辺と格子解像度から決まるため、計算領域が広がると1セルが大きくなることがあり、そのときは氷晶の細部が粗くなります。1セルの幅の決め方は「品質の選択」にあります。

ゆらぎは、各ステップでセルごとの水蒸気の量がわずかに増減する割合を決めます。増減の割合は、ゆらぎが100%のときに0.2%です。ゆらぎが0%のとき、氷晶の形は素材の形とパラメータだけで決まり、シードは形に影響しません。

シードは、どのセルで水蒸気を増やし、どのセルで減らすかを決める固定値です。増やすか減らすかは、シードとセル位置とステップだけで決まります。

### 5. 白濁・屈折・光沢・色

白濁は、氷が素材を覆い隠す度合いを決めます。氷の厚い部分ほど強くかかります。素材の内側も凍るので、白濁が強いと素材は見えにくくなります。

素材の外側には、氷越しに見える映像がありません。そこへ伸びた氷は白濁の色に光沢が乗って見え、白濁が強いほど濃くなります。白濁を0%にすると、素材の外側の氷は光沢も含めて見えなくなります。ただし縁のすぐ近くでは、屈折でずれた素材が氷に映り込むため、見えることがあります。

屈折は、氷越しに見える素材の歪みの強さを決めます。氷の厚みの勾配から法線を求め、法線の向きに応じて素材を参照する位置をずらします。歪むのは素材だけで、下にある別のアイテムは歪みません。

光沢は、氷の表面に映る光の強さを決めます。照り返しは、左上の手前に固定した光と法線から計算します。

色は、白濁で覆った部分の色を決めます。色の不透明度は使いません。

### 6. 品質の選択

品質は、成長格子の解像度と成長ステップ数の上限をまとめて切り替えます。品質を変えると格子解像度が変わるため、氷晶の形も変わります。

| 品質 | 格子解像度 | 成長ステップ上限 |
|---|---:|---:|
| 標準 | 192 | 1200回 |
| 高品質 | 288 | 2048回 |
| 最高品質 | 384 | 3072回 |

格子解像度は、1セルの幅を決める数です。1セルの幅は、計算領域の長辺の画素数を格子解像度で割った長さで、1画素より小さくはなりません。格子解像度が大きいほど1セルが小さくなり、氷晶の細部まで表せます。

ステップ数は、到達距離がセル何個分にあたるかを求め、その24倍の整数部分に128を足した回数です。ただし192回を下回らず、品質の上限を超えません。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャおよび共有フェンスを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 核の判定には現在のフレームの不透明度だけを使用します。輝度と色は判定に影響しません。不透明度が5%を超える画素が1つでもあるセルを素材の内側とみなします。履歴フレーム、外部画像、学習済みモデルは使用しません。
- 計算領域は、透明な部分も含む素材全体の上下左右に、到達距離と80画素の余白を加えた大きさです。到達距離と余白をそのまま加えると計算領域の長辺が8192画素を超えるときは、縁から霜が広がる距離の上限を設定より短くして計算します。ただし計算領域を決めるときは、この上限を1セルの幅より短くせず、80画素の余白も必ず取ります。そのため、計算領域の長辺は8192画素を超えることがあり、最大で8408画素になります。素材の長辺が8160画素を超える場合は、エフェクトを適用せず入力映像を表示します。
- 処理量とGPUメモリ使用量は、計算領域の大きさと品質に応じて増えます。

## 注意事項

- 処理負荷: 最高品質は格子解像度と成長ステップ数の上限が最も大きいため、高品質と標準より処理負荷が高くなります。到達距離を大きくするほど計算領域が広がり、ステップ数も増えます。描画は、凍結度で表示している氷晶を囲む矩形の範囲だけで行います。
- キャッシュ: 素材の形と大きさ、品質、シード、樹枝化、ファセット、到達距離、ゆらぎが変わらないフレームでは、成長の計算を再利用します。ゆらぎが0%のときは、シードを変えても成長の計算を再利用します。強さ、凍結度、白濁、屈折、光沢、「色」だけを変えたフレームでは、成長を計算し直しません。素材の形が変わったかどうかは、素材の内側とみなしたセルの並びで判定し、成長の計算を再利用するフレームでも確かめます。素材の形が変わるフレームと、樹枝化、ファセット、到達距離、ゆらぎをアニメーションで変えたフレームでは、成長を毎回計算し直すため、処理が重くなります。
- 描き直し: 不透明な動画のように形を保ったまま色だけが変わる素材では、成長の計算を再利用し、氷の描画だけをやり直します。素材の色が変わったかどうかは、凍結度、白濁、屈折、光沢、「色」が前に氷を描いたときから変わっていないフレームで確かめます。これらのどれかが変わったフレームでは、素材の色を確かめずに氷を描き直します。強さだけを変えたフレームでは、氷を描き直さず、合成の量だけを変えます。成長を計算し直さず、凍結度も変わらないまま描き直しが続くときは、描画に使う氷の厚みと勾配を氷のかかる画素だけGPUメモリに保存します。次の描き直しからは、保存した値を使います。成長を計算し直すか凍結度が変わると、保存した値は破棄します。
- 凍結度0%と強さ0%: 凍結度が0%のときは何も描画しません。強さが0%のときは入力を変更しません。
- シードと再現性: 氷晶の形は、素材の形と大きさ、パラメータ、シード、セル位置、成長ステップから決定論的に算出します。時間値は結晶の生成に使用しません。
- 透明部分: 氷は素材の外側にも描画されるため、出力範囲は素材より広がります。素材の外側の氷は白濁が強いほど濃く見え、白濁が0%のときはほとんど見えません。氷は元映像の上へアルファ合成します。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、入力をつなぎ直すとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認では、更新情報の取得と比較で起きた例外は報告しません。通知の文を組み立てて表示するときに起きた例外は報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない、素材の長辺が8160画素を超えるときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらへも接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
