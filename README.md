# 氷晶成長 for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-CrystallineGrowth.svg)](https://github.com/routersys/YMM4-CrystallineGrowth/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、素材の輪郭を核形成点とみなし、Gravner–Griffeathの雪結晶成長モデルで氷晶を成長させて霜として描画する映像エフェクトプラグインです。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
氷晶の形はシードから決定論的に決まり、同じ設定では常に同じ形になります。
強さ、凍結度、樹枝化、ファセット、到達距離、ゆらぎ、白濁、屈折、光沢の9項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「氷晶成長」として表示されます。カテゴリは装飾とアニメーションです。

入力された現在のフレームのアルファ値から素材の輪郭を求め、輪郭のセルを核形成点として六方格子の上に置きます。成長の計算はGravner and Griffeathの論文「Modeling Snow Crystal Growth II: A mesoscopic lattice map with plausible dynamics」（2007年）のセルオートマトンに基づきます。各セルは付着フラグ、境界質量、結晶質量、拡散質量の4つの状態を持ち、水蒸気の拡散、凍結、異方性の付着、融解、ゆらぎの5つのステップを繰り返して氷晶を成長させます。成長は決定論的で、同じシードと同じパラメータでは常に同じ形になります。

凍結度のパラメータは、成長の記録をどこまで表示するかを決めます。各セルには付着したステップが記録されるため、凍結度を時間で変えると、素材が縁から凍りついていく遷移になります。求めた氷晶は、白濁、背景の屈折、表面の光沢を持つ氷として描画し、元映像の上へ合成します。

計算はComputeWeaveの計算シェーダーがDirect3D 12で実行します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。通常のフレーム処理では、CPUへの画素の読み戻しを行わず、付着ステップの記録だけを読み戻します。氷晶が存在する矩形の範囲だけを描画し、素材の形状とパラメータが変わらないフレームでは成長の計算を再利用します。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-CrystallineGrowth/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「氷晶成長」を選択してください。

## 主な機能

### 1. 氷晶の成長

現在のフレームのアルファ値から素材の輪郭を求め、輪郭のセルを核形成点として六方格子の上に置きます。格子は各セルが6つの隣接セルを持つ三角格子で、実際の氷の結晶構造と同じ六方対称の成長になります。

各セルは付着フラグ、境界質量、結晶質量、拡散質量の4つの状態を持ちます。1ステップの更新は、水蒸気の拡散、結晶境界での凍結、境界質量のしきい値による付着、融解、ゆらぎの順で行います。付着のしきい値は隣接する結晶セルの数で変わり、先端では高く、くぼみでは低くなります。この異方性が、実際の雪結晶に見られるファセットと樹枝の分岐を作ります。

外部マスクや手動の位置指定は必要としません。成長は品質設定が定めるステップ数を上限として、到達距離に応じた回数だけ進みます。

### 2. 凍結度による凍結の遷移

凍結度は、成長の記録をどこまで表示するかを決めます。0%では何も描画せず、値を上げると氷晶が素材の縁から外側と内側の両方へ伸びていきます。各セルには付着したステップが記録されるため、表示は成長の順序どおりに進みます。

凍結度を時間で変えると、テキストや立ち絵が端から凍りついていく演出になります。

### 3. 樹枝化とファセット

樹枝化は、格子を満たす水蒸気の密度を決めます。低いほど板状にまとまり、高いほど樹枝状に枝分かれします。

ファセットは、付着の異方性の強さを決めます。高いほど結晶面が平らに揃い、板状の輪郭になります。低いほど枝が細かく分かれます。2つのパラメータの組み合わせで、板状、扇状、樹枝状、シダ状の形を連続的に変えられます。

### 4. 到達距離とゆらぎ・シード

到達距離は、縁から霜が広がる距離を素材の長辺に対する割合で決めます。距離はジャンプフラッドで求めた縁からの距離で判定し、縁の外側と内側の両方に適用します。到達距離を大きくするほど計算領域が広がり、処理量が増えます。

ゆらぎは、水蒸気の拡散質量へ加える微小な変動の大きさを決めます。ゆらぎが0%のとき、氷晶の形は素材の輪郭とパラメータだけで決まり、シードは形に影響しません。

シードは、ゆらぎの内容を決める固定値です。ゆらぎとシードとセル位置から決定論的に変動を作るため、同じシードと同じパラメータでは常に同じ形になります。

### 5. 白濁・屈折・光沢・色

白濁は、氷の白さを決めます。結晶質量が多い部分ほど強く白くなります。

屈折は、氷を通した背景の歪みの強さを決めます。氷の厚みの勾配から法線を求め、法線の向きに応じて元映像の参照位置をずらします。

光沢は、氷の表面に映る光の強さを決めます。固定した光源の向きと法線から反射光を計算します。

色は、氷の色を決めます。白濁した部分が指定した色に染まります。

### 6. 品質の選択

品質は、成長格子の解像度と成長ステップ数の上限をまとめて切り替えます。

| 品質 | 格子解像度 | 成長ステップ上限 |
|---|---:|---:|
| 標準 | 192 | 1200回 |
| 高品質 | 288 | 2048回 |
| 最高品質 | 384 | 3072回 |

格子解像度は計算領域の長辺のセル数です。短辺のセル数は計算領域の縦横比に合わせて決めます。実際のステップ数は到達距離に応じて決まり、上限で打ち切ります。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャおよび共有フェンスを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 核形成点の判定には現在のフレームのアルファ値だけを使用します。輝度と色は判定に影響しません。履歴フレーム、外部画像、学習済みモデルは使用しません。
- 計算領域は素材の範囲に到達距離と描画の余白を加えた大きさで、長辺は8192画素が上限です。素材が大きく余白を確保できない場合は、エフェクトを適用せず入力映像を表示します。
- 処理量とGPUメモリ使用量は、計算領域の大きさと品質に応じて増えます。

## 注意事項

- 処理負荷: 最高品質は格子解像度と成長ステップ数が最も多いため、高品質と標準より処理負荷が高くなります。到達距離を大きくするほど計算領域が広がります。描画は氷晶が存在する矩形の範囲だけを計算します。
- キャッシュ: 素材の輪郭と結晶の形を決めるパラメータが変わらないフレームでは、成長の計算を再利用します。凍結度、白濁、屈折、光沢、色だけを変えたフレームでは、結晶を再計算しません。
- 凍結度0%と強さ0%: 凍結度が0%のときは何も描画しません。強さが0%のときは入力を変更しません。
- シードと再現性: 氷晶の形は、シード、セル位置、成長ステップから決定論的に算出します。時間値は結晶の生成に使用しません。
- 透明部分: 霜は素材の外側にも描画されるため、出力範囲は素材より広がります。氷は元映像の上へアルファ合成します。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。本プラグインがエフェクトのプロセッサを作るとき、フレームごとに更新するとき、入力をつなぎ直すとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない、計算領域が上限を超えるときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | GitHubへ接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避し、次回の起動時に送り直します。送信も再送も非同期に行うため、起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
